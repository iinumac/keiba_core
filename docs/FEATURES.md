# 特徴量の定義と論点

特徴量の計算は `src/keiba/features.py` に集約されている。
03（学習）と 04（戦略）は同じコードを呼び、設定だけ切り替える。

旧プロジェクトでは C03 と C04 がそれぞれ別に特徴量を書いており、
計算式は概ね同じなのに**欠損値の埋め方とクレンジング条件が食い違っていた**。
どちらかに寄せると予測が変わるため、差異を `FeatureConfig` として明示し、
従来どおりの挙動を `C03_CONFIG` / `C04_CONFIG` で再現できるようにしてある。

## C03_CONFIG と C04_CONFIG の違い

| 項目 | C03_CONFIG | C04_CONFIG | 旧実装での影響 |
|---|---|---|---|
| `surface` が芝でもダートでもない行 | `-1` | `0`（＝芝と同値） | 11,428行 |
| 新馬の3着内率の初期値 | 全体平均×0.5 ≒ **0.1065** | 固定 **0.24** | 全新馬。押し上げ力にも波及 |
| 特定騎手の除外 | あり | なし | 9,042行 |
| 着順が数値でない行（競走中止など） | 残す | 落とす | 6,669行 |
| `prev_finish` ほか前走情報の欠損 | 欠損のまま | 定数で補完（10 / 36.5 / 30.0 / 10 / 90） | 全新馬 |
| `impost` の欠損 | 55.0 | 0 | 欠損行のみ |
| 市場系特徴量 | なし | あり | — |

全体の3着内率は 0.2130。C04 の 0.24 は「新馬は平均より走る」という想定になっており、
C03 の「少し割引く」という考え方と逆を向いている。**どちらに寄せるかは未決。**

## 名前だけ違うもの

| C03 | C04 | 実体 |
|---|---|---|
| `surface_encoded` | `surface_code` | 同一。両方の名前で出力している |
| `horse_expected_top3_rate` | `horse_prev_top3_rate` | **完全に同じ値**（81,132行すべてで一致） |

> 別名を両方モデルに入れると、LightGBM は片方しか使わない。
> 実際に `horse_expected_top3_rate` は gain・split・AUC低下がすべて 0 だった。
> 重複と知らずに「この特徴量は効かない」と誤読する危険があるので、
> `MARKET_FREE_FEATURES` からは外してある。

## 主な特徴量

### `horse_expected_top3_rate`

その馬の**前走までの**3着内率。`shift().expanding().mean()` で求める。
`shift()` は当該レースの結果を含めないため。

### `jockey_added_value` / `trainer_added_value`

「そのレースの結果」から「馬の期待値」を引いた差の、過去累積平均。

```
added_value_in_race = is_top3 - horse_expected_top3_rate
jockey_added_value  = groupby(jockey_id).shift().expanding().mean()
```

騎手の腕を、乗った馬の能力を差し引いて測る狙い。

### 走破タイム・上がり3F（`speed_features=True`、既定で有効）

走破タイムは距離・馬場・馬場状態で水準がまるで違う
（ダ1000m 60.2秒 / ダ2000m 127.4秒）。そのままでは使えないので
**レース内で正規化**する。同じレースを走った馬との比較なので条件差が消え、
リークもない（レース結果は確定後に既知）。

```
time_z   = -(タイム - レース平均) / レース標準偏差   速いほど大きい
last3f_z = -(上がり - レース平均) / レース標準偏差
```

そのうえで馬ごとに過去を集計する（`shift()` で当該レースを含めない）。

| 特徴量 | 内容 | AUC低下 |
|---|---|---|
| **`r3_time_z`** | 直近3走のタイム偏差の平均 | **0.0329** |
| `avg_time_z` | 過去平均 | 0.0067 |
| `best_time_z` | 過去最高 | — |
| **`best_last_3f`** | 過去最速の上がり（絶対値） | **0.0088** |
| `r3_l3f_z` / `avg_l3f_z` / `best_l3f_z` | 上がりの偏差 | — |

**`r3_time_z` は `prev_finish`（0.0300）を上回る最重要特徴量。**
市場フリーモデルの AUC は 0.7417 → 0.7527 に改善する。

ただし市場込みモデルには効かない（0.8212 → 0.8209）。
市場は既にタイムと上がりを織り込んでいる。詳細は [`MARKET.md`](MARKET.md)。

### 市場系（C04_CONFIG のみ）

| | 内容 |
|---|---|
| `market_implied_win_prob` | `(1 - 控除率) / オッズ`。市場が見積もる勝率 |
| `odds_ratio_to_fav` | 1番人気とのオッズ比。**オッズ断層の指標** |
| `pop_odds_mismatch` | 人気とオッズの乖離 |

## 未決の論点

### 1. マスタ出力の `shift()`

マスタは「各馬・騎手・調教師の最新評価値」だが、`shift()` の影響で
**その対象の最新レースが反映されない**（1レース分古い）。

学習時は `shift()` が必須（リーク防止）だが、予測時のマスタは完了済みレースを
全部含むのが筋であり、ここは設計判断が要る。

### 2. 新馬の初期値

上表のとおり 0.1065 と 0.24 で乖離が大きい。

### 3. `is_debut` の判定

旧 C03 は `prev_finish.isna()` で新馬を判定していた。`prev_finish` は前走の着順
なので、**前走が競走中止・除外・取消だった馬も欠損**になり、新馬と誤判定される。
実データで 3,678 行が該当し、旧 C03 は新馬を学習から除外する仕様のため
学習データが 3,382 行目減りしていた。

本プロジェクトの既定は**出走回数（cumcount）ベース**でこの取りこぼしが無い。
`FeatureConfig.debut_from_prev_finish=True` で旧挙動を再現できる。

### 4. まだ特徴量になっていない観点

旧プロジェクトのアーカイブ（`_archive_keiba_2025/python/`）にある分析軸で、
現在どの設定にも入っていないもの。

| 観点 | 補足 |
|---|---|
| **馬場状態 × 波乱度** | 本プロジェクトの 90 で検証済み。不良7.42% > 重6.56% > 稍重6.12% > 良5.95%（芝・6番人気以下の3着内率）。**効果が確認できたので特徴量化の価値がある** |
| コース × 枠順バイアス | 90 の例2で見られる |
| 距離替わり | 前走との距離差。現在は距離の絶対値しか持っていない |
| 馬体重増減 | 現在は絶対値のみ |
| 芝⇔ダート替わり | 現在は当該レースの馬場のみ |
