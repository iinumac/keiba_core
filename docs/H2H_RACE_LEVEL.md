# 対戦比較とレースレベル

出走馬を「過去の対戦」でつないで比べる試み。2026-10-04 のセッションで作成・検証した。

2つのアプローチを作った。

| | 単位 | 問い | モジュール |
|---|---|---|---|
| 対戦比較（h2h） | 馬 × 馬 | AとBはどちらが先着するか | `src/keiba/h2h.py` |
| レースレベル | レース | 宝塚記念組と天皇賞(春)組のどちらを重く見るか | `src/keiba/race_level.py` |

**結論を先に:** どちらも成り立つし、着差の大きさには意味がある。ただし単独では
人気（オッズ）での予想に及ばない。オッズに上乗せできる情報はわずかにある。
「格上のレースから来た」こと自体には予測力がほぼ無く、**レベルから着差を引いた
「前走パフォーマンス」で比べる**のが正しい使い方。

## ファイル

| ファイル | 役割 |
|---|---|
| `src/keiba/h2h.py` | 対戦比較の本体（`History`, `estimate`, `win_prob`, `rank`） |
| `scripts/h2h_rank.py` | レースを指定して序列と根拠を表示 |
| `scripts/h2h_eval.py` | 対戦比較の検証 |
| `src/keiba/race_level.py` | レースレベルの本体（`prepare_runs`, `fit`, `next_run_stats`） |
| `scripts/race_level_show.py` | 出走馬の前走レベル・前走パフォーマンスを表示 |
| `scripts/race_level_eval.py` | レースレベルの検証 |

目線ごとの上位3頭（`keiba.views`、`scripts/views.py`）に、前走パフォーマンス・能力・対戦比較の目線として組み込んである。

```bash
# 対戦比較
python scripts/h2h_rank.py 202609030411                              # 過去レース（実着順も並ぶ）
python scripts/h2h_rank.py 202609030411 メイショウタバル クロワデュノール  # 2頭の比較の根拠
python scripts/h2h_rank.py shutuba [data/shutuba/xxx.json] [race_id]  # 出馬表
python scripts/h2h_eval.py [レース数=600] [開始日=2025-01-01]          # 3000で約100秒

# レースレベル
python scripts/race_level_show.py 202608040211 2026-10-04   # 出馬表（netkeiba から取得。日付が必要）
python scripts/race_level_show.py 202609030411              # ウェアハウスにある過去レース
python scripts/race_level_eval.py [開始日=2025-01-01]       # 約10秒
```

race_id は netkeiba 形式（`YYYY` + 場2桁 + 回2桁 + 日2桁 + R2桁）。
keibalab の URL（`/db/race/YYYYMMDD場R/`）は日付ベースで形式が違う。
例: keibalab `202610040811` = 2026-10-04 京都11R = netkeiba `202608040211`（京都大賞典）。
対応は `shutuba.race_ids_on(date, Fetcher())` で当日の race_id を引いて確かめる。

## 1. 対戦比較（h2h）

### 経緯

ユーザーの発案した3段階の序列づけをそのまま実装した。

1. 直接対決で勝ったことのある馬が、もう一度その馬に勝つ確率で並べる
2. 直接対決が無ければ、共通の相手Cとの関係で比べる
   （AはCに勝ち、BはCに負けた／AはCに0.5秒勝ち、Bは0.2秒勝ち → Aが上）
3. それも無ければ、共通の馬が出てくる別のレースまで遡る

### 方法

```
段階1 直接対決     A と B が同じレースを走った        m(A,B)
段階2 共通の相手   A–C と B–C が走った                m(A,C) − m(B,C)   （Cが複数なら平均）
段階3 2頭はさむ   A–C, C–D, D–B が走った             m(A,C) + m(C,D) + m(D,B)   （最大200経路の平均）
```

- m(X,Y) = X が Y に何秒先着したか（走破タイム差）の平均。±2秒で打ち切る（大敗馬は流している）
- 浅い段階があればそれだけを使う
- 判定日より前・過去730日のレースだけ。障害レースは除外（`surface` は芝/ダートのままなので `race_name` の「障害」で判定）
- 推定着差 → 先着確率はロジスティック `P = 1/(1+exp(−k·着差))`。k は検証で当てはめ: 段階1 0.70 / 段階2 0.64 / 段階3 0.79（1秒差でおよそ66〜69%）
- 序列の score = 他の各馬に先着する確率の平均。比較できない相手は 0.5

### 検証結果（2025-01 以降の3,000レース・14万組、各レース前のデータのみで判定）

比較できた割合: 直接 11% / 共通の相手 47% / 2頭はさむ 24% / 比較できず 18%

| 推定着差 | 直接対決 | 共通の相手 | 2頭はさむ |
|---|---|---|---|
| 〜0.2秒 | 53.8% | 52.3% | 52.8% |
| 0.2〜0.5秒 | 57.7% | 57.5% | 58.6% |
| 0.5〜1.0秒 | 65.9% | 64.8% | 66.5% |
| 1.0〜2.0秒 | 72.7% | 71.2% | 76.7% |
| 全体 | 62.4% | 62.5% | 67.0% |
| 同じ組を人気で予想 | 67.7% | 69.2% | 71.6% |

- 前に勝った馬が再び勝つ確率は約62%。0.2秒以内の僅差ならほぼ五分、1秒以上なら7割超
- 対戦回数が2回以上でも的中率は上がらない（約60%）
- 共通の相手経由でも直接対決とほぼ同じ精度。ユーザーの仮説（着差の差で比べる）は成り立つ
- レース単位: 序列1位の勝率 23.2%・3着内 52.6%、1番人気は 33.4%・65.0%。序列1位と1番人気の一致は 38.8%
- **どの段階でも人気に負ける**。対戦成績はオッズにほぼ織り込まれている

## 2. レースレベル

### 経緯

対戦比較のあと、ユーザーが観点を変えた。京都大賞典（2026-10-04）の出馬表に
宝塚記念組と天皇賞(春)組がいて、どちらのレースが上か比べられれば、どちらを重用すべきか判断できる、という発想。

既存の `figure.py`（速度指数）は時計の速さでレースを比べるもの。今回は
対戦比較と同じ考え方で、**同じ馬が走った別々のレースを介してレース同士を比べる**方法にした。

### 方法

全レース・全馬について次の式を同時に最小二乗で解く（`scipy.sparse.linalg.lsqr`、damp=0.3）。

```
勝ち馬との差[馬, レース] = レベル[レース] − 能力[馬] + 誤差
```

- 単位は **1000mあたりの秒**（`figure` と同じ）。勝ち馬との差は 1.0秒/1000m で打ち切り
- レベル: そのレースの勝ち馬がどれだけ強いレースをしたか。大きいほど強いレース
- 能力: 馬の地力。期間内（過去730日）は一定とみなす
- **前走パフォーマンス = 前走レベル − 前走の勝ち馬との差**。その馬が前走で見せた強さ
- 能力の中央値を 0 にそろえる。2年分（約6,700レース・1.6万頭）を約0.05秒で解く。収束も確認済み（許容誤差を厳しくしても最大差 0.0007）
- 妥当性の確認: クラス（`level_score`）が上がるほどレベルの平均も上がる（1: 0.65 → 6: 1.17）
- `next_run_stats` は補助指標で、レースの出走馬が次走で勝った・3着内に入った頭数を数える

### 検証結果（2025-01〜2026-09 の5,393レース・46万組、前走が別レースの組だけ。週ごとに解き直し）

| 指標（上の馬が先着した割合） | 全レース | 重賞のみ |
|---|---|---|
| 人気 | 70.3% | 67.6% |
| 能力（過去2年） | 66.4% | 64.3% |
| **前走パフォーマンス** | 65.2% | **62.0%** |
| 前走着順 | 65.4% | 58.6% |
| 前走の勝ち馬との差 | 65.3% | 58.9% |
| 前走クラス（level_score） | 50.4% | 54.8% |
| 前走レベル | 51.1% | 53.8% |
| 前走メンバーのその後（次走3着内率） | 51.1% | 49.9% |

- 「格上のレースで負けた馬」と「格下のレースで好走した馬」がぶつかったとき（前走レベル差0.1以上、18万組）:
  格上組の先着は **40.9%**（重賞 48.1%）。前走パフォーマンスで上の方は 62.4%（重賞 58.6%）、人気は 68.5%（重賞 64.8%）
- オッズへの上乗せ（2025年で学習し、2026年で評価したロジスティック回帰）:

  | モデル | logloss | AUC |
  |---|---|---|
  | オッズのみ | 0.5688 | 0.7714 |
  | + 前走パフォーマンス | 0.5672 | 0.7729 |
  | + 前走レベル・差 | 0.5672 | 0.7729 |
  | + 能力 | 0.5679 | 0.7722 |
  | + 能力・前走パフォーマンス | 0.5669 | 0.7732 |

  前走レベル・差モデルの係数は、レベル +0.66、差 +0.39（1000mあたり秒）。オッズの上では、レベルの方が着差より重く効いている

### 実例: 京都大賞典 2026-10-04（netkeiba 202608040211、芝2400m・18頭）

2400m換算の秒。

| 前走 | レベル | 着順 | 勝ち馬との差 | 前走パフォ |
|---|---|---|---|---|
| 宝塚記念組（ファミリータイム、マイネルエンペラー、ミクニインスパイア、ミステリーウェイ） | **3.45** | 6・10・12・16 | 1.5〜2.4 | 1.05〜1.92 |
| 天皇賞(春)組（ヴェルテンベルク、アクアヴァーナル、ヘデントール） | 2.47 | 2・4・5 | 0〜0.3 | **2.17〜2.47** |

レースとしては宝塚記念が約1秒上だが、宝塚組は大きく負けている。前走パフォの上位3頭は天皇賞(春)組で、
宝塚組の最上位はファミリータイムの5番目。能力の上位は ヘデントール 2.31、ショウナンラプンタ 2.30。

**結果:** 1着 エコロディノス（11番人気）、2着 マイネルエンペラー（8番人気・宝塚記念10着）、
3着 アクアヴァーナル（2番人気・天皇賞(春)4着）、5着 ヘデントール（5番人気・能力1位）。
前走パフォでは下位だった宝塚記念組が2着に来た。前走で大きく負けても、レースのレベルの高さが
効いた例とも読める（オッズ上のロジスティック回帰でも、レベルの係数 +0.66 が着差の +0.39 より重い）。
1レースなので結論にはしない。

## 注意点・既知の限界

- **距離適性を補正していない。** 3200m の天皇賞(春)で着差が小さかった長距離馬が、2400m で同じように走れるとは限らない
- 着差の打ち切りで、大敗馬の差が小さく出る（京都大賞典ではミステリーウェイ・ミクニインスパイアが打ち切りに当たっている）
- 障害レースは除外しているので、「前走」は直近の平地戦になる（例: メイショウブレゲは障害戦が直近だが、表示は阪神大賞典）
- 能力は730日間一定とみなすので、成長・衰えは追えない
- 取消・除外馬（着順が空）も出走表には並ぶ
- h2h の段階3は経路数の上限が200で、つながりが多い馬では偏る可能性がある

## 次の候補

- 前走距離と今回距離の差を加味する（例: 3200m → 2400m の割引）。最も効きそう
- 最近の対戦・レースを重く見る（時間減衰）
- 芝/ダート・距離帯が近いレースに絞る
- 前走パフォーマンス・能力・h2h の推定着差を既存の3着内確率モデル（`features.py`）の特徴量に加え、上乗せを測る
