# keiba_prediction からの移行

2026-09-27 に、旧 `keiba_prediction` の C01〜C04 を作り直したもの。

生HTML 55,435 ファイルは再ダウンロードせず、旧プロジェクトから
**ハードリンクで複製**した（`cp -al`）。同じ inode を共有するため
ディスク消費は増えない。

## なぜ作り直したか

旧プロジェクトを整理する過程で、設計に起因する問題が複数見つかった。
個別に直すより、データ層を組み直す方が早いと判断した。

### 1. C01 が取得した HTML を保存していなかった

HTML は Colab のランタイム上に置かれたままで、GitHub に入っていなかった。
このため次の3つが起きていた。

- ランタイム終了と同時に HTML が消える
- C02 はリポジトリを clone し直すため、**別ランタイムで実行すると
  C01 の成果が見えない**（同一ランタイムでの実行が暗黙の前提だった）
- C01 の skip 判定はディスク上の HTML の有無で行うため、**毎回同じレースを
  再ダウンロード**する

実害として、`races.parquet` の 2026年 594 レースに対し HTML は 162 件しかなく、
**432 レース分の HTML が失われていた**。

### 2. race_id の総当たり

race_id を機械的に組み立てて1件ずつ存在確認していた。年あたり

```
10競馬場 × 10開催回 × 20日 × 12レース = 24,000 通り
```

大半が空振りになる。netkeiba から 403 を返される主因はこれだった。

### 3. 特徴量の二重実装

C03 と C04 が別々に特徴量を定義しており、欠損値の埋め方やクレンジング条件が
食い違っていた。詳細は [`FEATURES.md`](FEATURES.md)。

### 4. 空ページの取り込み

netkeiba は結果が存在しないレースにも 200 で「枠だけのページ」を返す。
旧 `races.parquet` には、これに由来する日付 1970-01-01・レース名なしの行が
**69 件**混入していた。

### 5. コース表記の取りこぼし

パーサの正規表現が方向の後を1文字ぶんしか見ておらず、次の2つを解析できなかった。

| 表記 | どこ |
|---|---|
| `芝直線1000m` | 新潟の直線コース。「直線」で2文字 |
| `障芝 外-内2890m` | 障害戦。コース区分がハイフンで連結される |
| `芝右 内2周3600m` | 中山のステイヤーズS。距離の前に「2周」が入る |

該当レースは `surface` も `distance` も None になる。実データで **776 レース**、
うち **743 が新潟**。結果として次の2つが起きていた。

- **新潟の1000m戦が1件もデータに入っていない**（直線コースは2001年から使用）
- **ステイヤーズS（G2）が16年分すべて欠落**

旧プロジェクトも同じ正規表現だったため、同じ欠損を抱えたまま学習していた。

場当たり的な修正を繰り返さないよう、**全HTML 54,889件を走査してコース表記を
網羅**した。表記は14種類あり、現在の `parse.COURSE_RE` は全種を解析できる。
テストはこの定数を直接参照しており、式を二重に持たない。

| 修正の効果 | 前 | 後 |
|---|---|---|
| 新潟の1000m戦 | 0 | **420 レース** |
| 中山3600m（ステイヤーズS） | 0 | **16 レース** |
| `distance` が欠損 | 776 | **0** |

### 6. マスタ生成が非決定的

`sort_values('race_date').groupby(...).tail(1)` で最新行を取っていたが、
同一日に複数レースがある騎手（574人中356人）ではどの行を拾うかが
DataFrame の行順に依存していた。行順を変えると 246/574 で値が変わる。

## 変更点

| | 旧 | 新 |
|---|---|---|
| race_id の探索 | 総当たり（年24,000通り） | 開催日一覧から列挙（1日1リクエスト、約70レース） |
| HTML の保存 | していない | `gitpush` で GitHub へ |
| ノートブック間 | 同一ランタイム前提 | GitHub 経由。別ランタイム可 |
| 再パース判定 | race_id の突合のみ | ハッシュ + パーサ版のマニフェスト |
| パース | 逐次 | 並列（約180件/秒、全件5分） |
| ストア | 単一 parquet 2本 | 年パーティション + DuckDB |
| 特徴量 | C03/C04 で別実装 | `features.py` に集約 |
| 予想エンジン | 11,000文字のセル | `strategy.py` |
| 空ページ | 取り込む | `build.validate()` で除外 |
| コース表記 | 「直線」「外-内」を取りこぼし（776レース） | 解析できる。新潟1000m戦も入る |
| マスタの最新行 | 行順依存で不定 | `race_id` まで含めて決定的に |

## 検証

新ウェアハウスから作った特徴量を、旧 parquet から作ったものと突き合わせた。

| | |
|---|---|
| 共通キー | 751,880 行 |
| 完全一致 | `is_top3` / `prev_finish` / `prev_last_3f` / `days_since_last` / `is_jockey_changed` / `is_debut` / `surface_encoded` / `year` / `level_score` / `distance` |
| 差異あり | `horse_expected_top3_rate` / `jockey_added_value` / `trainer_added_value` |

差異は**旧にあって新に無い 501 レース**（HTML欠落 432 + 空ページ 69）に由来する。
これらは馬の履歴の累積平均に入るため、欠けるとその馬の以降の値が変わり、
騎手・調教師の押し上げ力にも波及する。**新側の計算が誤っているわけではない。**
